### S4 攻击面受控实验(拆解漏洞精确边界)
对同一 admin 令牌做六种变量组合,仅 **A** 被放行:

| 组 | header | payload | 签名 | 结果 |
|----|--------|---------|------|------|
| **A** | **alg=none** | **原 payload** | **空** | **✅ code=0 放行(P1 证据)** |
| B | 原(HS256) | 原 | 空 | 401 |
| C | 原 | 改(orgId) | 空 | 401 |
| D | alg=none | 原 | 原签名 | 401 |
| E | 原 | 原 | 截断 | 401 |
| F | 原 | 改 | 原签名 | 401 |

**结论**: Hutool 5.8.25 `JWTUtil.verify` 对"alg=none 头 + 空签名段 + 原 payload"返回 true。攻击者**不能伪造任意身份**(改 payload 仍 401),但**被截获的合法令牌可去掉签名并伪装 alg=none 重放,直至 `exp` 过期**(默认 720 分钟)。故定 **P1(重放)** 而非 P0(伪造)。

## 二、缺陷源码定位与修复

### S-1 🔴 JWT 空签名重放 — `JwtUtil.parseToken` L76-85
```java
if (!JWTUtil.verify(token, keyBytes())) { return null; }   // alg=none + 空签名 也返回 true
JWT jwt = JWTUtil.parseToken(token);
```
**修复**: verify 前解析 header 断言 `alg==HS256`,并断言 `token.split("\\.")[2]` 非空;生产强制 `HIS_JWT_SECRET`(配合 B7 弱密钥告警升级为拒启动)。
