# 多租户/多机构/RBAC/数据权限安全审计

审计对象:`framework/tenant`、`framework/config`(MP 租户插件)、`platform` 包(用户/角色/机构/任职授权)、全部 controller 的守卫覆盖、JdbcTemplate 原生 SQL、`application.yml` 与前端令牌存储。
核心结论:**租户维度有框架级兜底(80分),机构维度无框架兜底(55分),业务 RBAC 形同虚设(35分)**。租户隔离破坏面集中在 JdbcTemplate 原生 SQL 绕过插件;业务端点(收费/退费/发药/挂号/医保结算台)全部无服务端角色校验。

## P0 级问题

### P0-1 角色编码伪造 → 跨租户 SUPER_ADMIN 提权链
- 位置:`platform/service/SysRoleService.java:133-175`(去重仅按本租户查,全局预置角色 tenant_id=NULL 不被命中)、`SysRoleController.java:62-79`(仅需 ADMIN)、`framework/tenant/LoginUser.java:41-62`(hasRole 仅比对编码字符串)、`SysTenantController.java:63-69`(SUPER_ADMIN 可管理全部租户)
- 触发:医院 ADMIN 自建 `role_code='SUPER_ADMIN'` 角色 → 绑到自己 → 重新登录 → 可管理全部租户、跨租户开通/停用、DeptScopeResolver.isUnrestricted 全放行。`SysUserController.java:133,158` roleIds 亦未校验角色归属租户。
- 修复:create/update 拒绝保留编码集(ADMIN/SUPER_ADMIN/ORG_ADMIN/DOCTOR/CASHIER…);hasRole 对高权编码校验来源角色 tenant_id IS NULL;UserSaveReq.roleIds 校验角色属于本租户或全局。

### P0-2 收费端 billDetail 原生 SQL 无 tenant_id → 跨租户读患者身份与费用
- 位置:`service/cashier/CashierService.java:179-233`(his_visit/his_patient/his_prescription_item/his_order_item 三段 SQL 均无 tenant_id),入口 `controller/cashier/CashierController.java:54-57`
- 触发:租户 A 任意登录用户按全局自增 visitId 枚举,拉取租户 B 患者姓名/身份证/参保类型/全部费用明细。
- 修复:补 `AND v.tenant_id = ?`;建立"JdbcTemplate SQL 必须显式携带 tenant_id"规约并全库扫描整改。

### P0-3 医生站就诊接口零科室/机构/主治校验 → 全医共体病历可遍历
- 位置:`controller/doctor/HisVisitController.java:45-103`(queue/detail/start/finish/save-draft/history/fee-summary/insu-info 无守卫);`service/doctor/HisVisitService.java:71-85`(queuePage 无机构过滤);前端 `static/js/views/doctor/queue-panel.js:115` 拉全租户队列
- 问题:doctor/outpatient 控制器完全不引用 DeptScopeResolver/OrgAccessGuard。任意登录用户可读任意就诊病历/诊断/处方/医嘱、把他人候诊改接诊并写病历、查任意患者历史与参保信息。
- 修复:queuePage 强制注入会话机构 + DeptScopeResolver.currentAuthDeptIds();detail/start/finish/save-draft/history/fee-summary/insu-info 加机构+科室+主治归属校验。

### P0-4 药房发药详情原生 SQL 无 tenant_id → 跨租户读处方与库存
- 位置:`service/pharmacy/PharmacyService.java:152-177`(dispenseDetail 无 tenant_id;同文件 238-241 有,属遗漏),入口 `controller/pharmacy/PharmacyController.java:68-74`
- 修复:补 tenant_id;pharmacyId 强制走 WarehouseAccessService.requirePharmacyAccess。

### P0-5 业务 API 整体无服务端角色鉴权(前端隐藏、接口直调)
- 位置:收费 `CashierController.java:60-83,164-169`;发药/退药 `PharmacyController.java:104-156`;挂号/退号 `HisRegistrationController.java:38-107`;患者档案 `HisPatientController.java:29-87`;护士执行 `NurseExecController.java:60-84`;医保结算台 `OutpatientController.java:27-66`(2201-2208 的 psnNo/setlId 完全由客户端提供,无租户/机构绑定)
- 问题:AuthInterceptor 只验令牌有效性不验角色;菜单按角色下发只是前端导航。
- 触发:REGISTRAR 直调退费退掉任意收费单;DOCTOR 直调日结;任意用户用他人 setlId 调 2208 撤销医保结算。
- 修复:统一角色鉴权注解/拦截器(按端点标注 CASHIER/PHARMACIST/DOCTOR/NURSE/REGISTRAR);2201-2208 台加租户+机构绑定校验或限 SUPER_ADMIN。

### P0-6 默认管理员凭证硬编码并明文写日志

### P0-7 JWT 密钥为公开默认值 → 令牌可伪造

## P1 级问题

- **P1-1 科室授权"唯一判权口径"DeptScopeResolver 未落地临床域**:全库仅 warehouse/WarehouseAccessService 与 StaffEmploymentController 两处调用;doctor/outpatient/nurse/treatment/medtech 全部绕过。需将 currentAuthDeptIds() 接入 visit/queue/prescription/order 查询构造。
- **P1-2 收费链路机构口径不一致**:charge 的 orgId 取请求值不校验就诊所属机构(`CashierService.java:439`),可跨机构收费落账;退费守卫在 orgId 为 null 时整段跳过(`CashierService.java:661-662`),应 fail-closed。
- **P1-3 机构/角色/菜单写守卫口径不统一**:机构 CRUD 用 requireAdmin(`SysOrgController.java:109-114`)、用户/科室用 requireLeadWrite、医保配置用 requireTenantConfigAdmin;hasRole(ADMIN) 不看会话机构,多角色用户切到成员机构后仍持 ADMIN 判权。
- **P1-4 无审计日志体系**:收费/退费/日结仅 log.info;权限变更零留痕。需统一操作日志表 + 切面,覆盖资金类与平台管理端点。
- **P1-5 账号停用/密码重置不吊销已发令牌**:AuthInterceptor 只验签名与有效期;resetPassword/updateStatus 不落令牌版本;switchOrg 不复查用户/租户 status。停用用户 12 小时内仍可全额退费。
- **P1-6 登录无防爆破**:AuthService 无失败计数/锁定/验证码;login_fail_lock_count=5、session_timeout=30 参数定义而未实现。
- **P1-7 任职/临调授权写入不校验 org_id/dept_id 属于本租户**(`StaffEmploymentService.java:217-254,266-288`)。
- **P1-8 医保 SM2 私钥明文落库**:sys_tenant.sm2_private_key / sys_org.sm2_private_key 明文存 MySQL(响应侧已掩码,但存储明文)。需应用主密钥加密存储或本地加密文件。
- **P1-9 前端令牌存 localStorage + 菜单隐藏即唯一闸门**:`static/js/app.js:206,328-330`;多处 innerHTML 拼接存在 XSS 取令牌风险。令牌改 httpOnly Cookie;innerHTML 统一转义。

## P2 级问题

- 租户插件上下文为空时回退 `tenant_id=0`(`MybatisPlusConfig.java:50-52`),后台线程写数据会写成 0 或查不到,建议 fail 语义。
- 全局异常处理器回传原始异常消息(`GlobalExceptionHandler.java:29`),可能泄露 SQL/表结构。
- `/uploads/**` 免鉴权静态映射(医生签名/头像匿名可拉取)。
- 分页上限 10 万 + LIKE 未转义 %/_(`SysUserController.java:85`、`SysUserService.java:75-77`)。
- `SysRoleService.update` 允许把自定义角色改名为保留编码(P0-1 第二入口)。
- 医保测试台面(`QueryController.java:48-59`、`DictController.java:25-61`)仅登录即可用,字典下载会触发真实平台调用。
- 无 CORS/限流配置。

## 整改顺序建议

1. P0-1 提权 → 2. P0-5 业务角色闸门 → 3. P0-2/P0-3/P0-4 跨租户/跨机构数据面 → 4. P0-6/7/8 凭证与密钥 → 5. P1 审计日志与口径统一。
