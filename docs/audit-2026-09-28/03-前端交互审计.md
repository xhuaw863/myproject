# 前端门诊业务流与交互正确性审计

审计对象:`static/index.html`、`static/js/app.js`、`static/js/api.js`、`static/js/views/*.js`,与后端 controller/service 交叉验证(HisPrescription/HisVisit/HisOrder/HisRegistration/Cashier/SysOrg)。

**成熟度总评:中等偏上**。工程骨架健康(统一 api.js 拦截器、401 全局处理、Vue+Element Plus IIFE 无构建组织清晰);资金显示遵循"后端权威"原则(退费金额不可编辑、多支付拆分容差 0.005、医保/自费分流正确);重复提交防护覆盖率约 85%;XSS 面整体安全(Vue 插值天然转义,仅 ElMessageBox 一处系统性遗漏)。**交互正确性 80/100,资金与安全 85/100,体验与边界 70/100**。

## P0(资金级)

### P0-1 处方拆方顺序创建非原子,部分失败后重试会重复开立
- 位置:`static/js/views/doctor/prescription-panel.js:604-624`(savePrescription)
- 问题:西药批与中药饮片批拆成多次 POST `/api/his/prescription/create` promise-reduce 顺序提交;第 1 批成功、第 2 批失败(网络中断/药品停用)无回滚;rxItems 仅成功路径清空(L617),失败时草稿残留。
- 触发:"西药+饮片"混合处方,第 2 批被拒 → 医生看到"开立失败"但第 1 批已落库 → 修正后重试 → 第 1 批重复创建 → **重复收费**。
- 修复:后端提供整方批量创建事务接口(一次 POST 原子落库);前端失败时明确提示"已开立 1/2、第 2 张失败";提交体携带客户端幂等键(uuid)由后端防重。

### P0-2 平台端用户新增无防重复提交
- 位置:`static/js/views/platform.js:498-514`(submit)、`529-535`(toggleStatus)
- 问题:submit 无 saving 标志、确定按钮未绑 `:loading`,双击并发两次 POST `/api/sys/user`。
- 修复:加 `vm.saving` + `el-button :loading` + finally 复位;toggleStatus 同。

## P1

- **P1-1 收费台/收费工作台 ElMessageBox 存储型 XSS(7 处)**:`cashier.js:285-292,465-470,548-553,865-867`、`charge-workstation.js:334,382,445` — `dangerouslyUseHTMLString:true` 拼接未转义患者姓名/发票池号。患者姓名录入 `<img onerror=...>` 载荷即可在收费确认框执行脚本(可代发退费、窃会话)。修复:改 `dangerouslyUseHTMLString:false` 或先转义(项目内 catalog-map.js escText 是现成范例)。
- **P1-2 "提交病历"误导性成功**:`doctor/emr-panel.js:348-352` emitSave(true) 发出后无条件先弹"已提交保存",后端失败又弹错误 → 医生看到双重提示,可能误信已保存关闭工作站丢病历。修复:成功提示移入 `.then()`。
- **P1-3 完成接诊(F4)不检查未开立医嘱草稿,静默丢弃**:`doctor.js:180-207` finishVisit 仅校验诊断与病历必填;prescription-panel rxItems / order-panel 草稿明细在内存中未提交时,完成后 currentVisit 刷新 → 草稿全丢、患者漏开药漏检查。修复:finishVisit 前调各面板 hasDirty() 弹确认;后端 /finish 增加诊断非空校验(现 HisVisitService.java:153-215 不校验)。
- **P1-4 检查/检验/治疗单开立不强制诊断**:`order-panel.js:374-383` validateOrder 诊断为空仅显示"尚未录入诊断"即放行;后端 order/create 亦无必填校验。医保 2204 申请单与报告单诊断栏将为空。修复:与处方口径一致拦截或 confirm 提示。
- **P1-5 过敏拦截接口失败静默放行(fail-open)**:`order-panel.js:283-303` checkAllergyConflict catch 返回空数组,过敏校验被跳过。修复:接口失败改为阻断并提示"过敏信息获取失败,是否强制开立(留痕)"。
- **P1-6 身份证/医保个人编号以 URL query 传参,落入访问日志**:`outpatient.js:745`(patient/page?keyword)、`825`(psnNo||idCard 作 keyword)、`851`(patient/by-idcard?idCard=完整身份证)。修复:改 POST body 查询 + 日志脱敏。
- **P1-7 登录页预填明文默认账号**:`app.js:184,232-233` loginForm 预置 admin/admin123、superadmin/admin123 明文展示。(与安全审计 P0-6 同源,前端侧修复:删预填改 placeholder)
- **P1-8 机构管理删除用户无确认、写按钮未按角色隐藏**:`platform.js:536-540` remove 无 confirm 无防抖;`org.js` 模板 L232/L258-260 新增/编辑/删除按钮对非管理员可见(后端 requireAdmin 兜底 → 点击得 403)。修复:remove 加 confirm+loading;org.js 按 lead/canMaintain v-if 隐藏。

## 已确认正确的设计(审计对照)

- **资金权威口径正确**:最终金额均以服务端返回展示;退费全额由后端决定(RefundReq{billId,reason} 无金额字段);部分退费金额服务端重算。
- **重复提交防护大多到位**:收费/退费/日结/排班/模板/文书开具均有 saving/submitting + :loading;日结确认与服务端结算分离。
- **挂号并发安全**:前端重复挂号预检 + 后端同号源重复拦截 + 原子 UPDATE left_num>0 扣减(HisRegistrationService.java:256-311);退号原子回滚限 total_num 上限。
- **权限双层**:platform.js/cashier.js/basedata.js 前端按角色隐藏 + 后端 requireLeadWrite/requireAdmin/403 兜底;机构切换 onSwitchOrg 重取令牌并 location.reload() 全量刷新。
- **XSS 整体安全**:Vue 插值天然转义;hl() 先转义再包 <mark>;token 走 Authorization 头;密码走 POST body。
- **医保/自费分流正确**:医保走 /charge(2206→2207),自费走 /self-pay;INSURANCE 不在用户可选支付方式。
